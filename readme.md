# Как работает DNS: руководство и справочник

**DNS (Domain Name System)** — это система доменных имен, которая переводит понятные человеку адреса сайтов в числовые IP-адреса, понятные компьютерам. Без нее для открытия любого ресурса пришлось бы запоминать длинные комбинации цифр вместо привычных названий.

## Зачем нужен DNS

Устройства в интернете находят друг друга по уникальным IP-адресам (например, `192.0.2.1` или `2001:db8::1`). Людям сложно удерживать в памяти десятки таких комбинаций. 

Система DNS работает как **глобальная телефонная книга интернета**: вы вводите имя контакта (домен), а система сама находит нужный номер телефона (IP-адрес) и соединяет вас с сервером.

---

## Как происходит поиск сайта: 4 основных шага

Когда вы вводите адрес сайта в браузере и нажимаете **Enter**, система за доли секунды проходит через цепочку серверов.

1. **Проверка локального кэша.** Сначала браузер и операционная система проверяют, не заходили ли вы на этот сайт недавно. Если запись сохранилась в памяти устройства, страница откроется сразу.
2. **Обращение к DNS-резолверу.** Если в кэше пусто, запрос отправляется резолверу — специальному серверу вашего интернет-провайдера или публичной службы (например, `8.8.8.8`). Он берет на себя всю дальнейшую работу по поиску.
3. **Поиск по иерархии серверов.** Резолвер последовательно опрашивает три уровня серверов:
   * **Корневой сервер (Root)** — подсказывает, где искать информацию о нужной доменной зоне (например, `.ru`, `.by` или `.com`).
   * **Сервер доменной зоны (TLD)** — направляет резолвер к конкретному серверу, который отвечает за искомый домен.
   * **Авторитетный DNS-сервер** — хранит финальную информацию о домене и возвращает резолверу точный IP-адрес сайта.
4. **Загрузка страницы.** Резолвер передает полученный IP-адрес вашему браузеру и сохраняет его в свой кэш на будущее. Браузер подключается к серверу сайта по этому адресу и загружает страницу.

## Глубокое погружение: справочные таблицы

Для настройки собственного домена, корпоративной почты или диагностики сетевых проблем полезно разбираться в типах DNS-записей и ролях серверов.

### Основные типы DNS-записей

| Тип записи | Расшифровка | Назначение | Пример значения |
| :--- | :--- | :--- | :--- |
| **A** | Address | Связывает доменное имя с IP-адресом формата IPv4. | `93.184.216.34` |
| **AAAA** | IPv6 Address | Связывает доменное имя с IP-адресом формата IPv6. | `2606:2800:220:1:248:1893:25c8:1946` |
| **CNAME** | Canonical Name | Перенаправляет один домен (обычно поддомен) на другой домен. | `://example.com` -> `example.com` |
| **MX** | Mail Exchange | Указывает почтовые серверы, которые принимают письма для домена. | `10 ://example.com` |
| **TXT** | Text | Хранит текстовую информацию для подтверждения прав на домен и защиты почты (SPF, DKIM). | `v=spf1 include:_://example.com ~all` |
| **NS** | Name Server | Определяет авторитетные DNS-серверы, которые управляют настройками этого домена. | `://hosting.com` |

### Ключевые параметры и понятия DNS

| Термин | Что означает | На что влияет |
| :--- | :--- | :--- |
| **TTL (Time to Live)** | Время жизни записи в секундах. | Определяет, как долго серверы и браузеры будут хранить IP-адрес в кэше перед повторным запросом. |
| **DNS-резолвер** | Рекурсивный сервер-посредник. | Принимает запрос от пользователя и самостоятельно опрашивает цепочку серверов до получения ответа. |
| **Авторитетный сервер** | Конечный источник данных о домене. | Хранит реальные DNS-записи, которые настраивает владелец сайта или администратор. |
| **Распространение DNS** | Обновление информации в глобальной сети. | После изменения записей новые данные могут применяться от нескольких минут до 48 часов из-за кэширования. |

## Частые ошибки при настройке DNS

Даже небольшая опечатка в панели управления доменом может сделать сайт или почту недоступными. Проверьте эти типичные проблемы, если настройки не работают:

* **Конфликт CNAME с другими записями.** Запись типа `CNAME` нельзя создавать для корневого домена (например, `example.com`), если для него уже заданы записи `MX` или `NS`. Используйте `CNAME` только для поддоменов (например, `www` или `blog`).
* **Указание IP-адреса в CNAME или MX.** Эти записи должны указывать строго на доменное имя (например, `://example.com`), а не на набор цифр. Для привязки к IP-адресу используйте только записи `A` или `AAAA`.
* **Забытая точка в конце домена (FQDN).** В некоторых DNS-панелях требуется ставить точку в конце полного доменного имени (например, `://example.com.`). Без нее система может автоматически дописать имя вашего домена еще раз, создав неверный адрес `://example.com.example.com`.
* **Отсутствие или неверный приоритет MX-записей.** Если у домена несколько почтовых серверов, для каждого нужно указать числовой приоритет (например, `10` и `20`). Чем меньше число, тем выше приоритет сервера при доставке писем.
* **Слишком высокий TTL перед переездом.** Если перед переносом сайта на новый сервер установлено большое значение TTL (например, `86400` секунд — 24 часа), пользователи еще сутки будут попадать на старый сервер. Снизьте TTL до `300` секунд (5 минут) за день до запланированных работ.
* **Редактирование записей не на тех NS-серверах.** Если домен делегирован на сторонний хостинг или CDN (указаны его `NS`-записи), менять `A`- или `MX`-записи в панели регистратора бесполезно. Все изменения нужно вносить там, куда ведут текущие `NS`-серверы.
